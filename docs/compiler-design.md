# Compiler design in KPCL

This document maps standard Compiler Design theory to the implementation under `backend/apps/compiler/`.

## What is lexical analysis?

Lexical analysis (scanning) converts a character stream into **tokens**. The KPCL lexer (`lexer.py`) skips whitespace, groups letters/digits into lexemes, and classifies them.

Example:

```
Input:  PARK CAR101 SLOT05
Tokens: KEYWORD(PARK), VEHICLE_ID(CAR101), SLOT_ID(SLOT05)
```

Invalid character example implemented in tests:

```
P@RK CAR101 SLOT05  →  Lexical Error: Invalid character '@'
```

Each token stores `token_type`, `lexeme`, and `position` (`tokens.py`).

## What are tokens?

A token is the smallest meaningful unit for the parser: a keyword, an identifier class, or a number. The parser never sees raw characters.

## What is syntax analysis?

Syntax analysis (parsing) checks whether the token sequence belongs to the language generated by a **context-free grammar**. KPCL uses a recursive-descent parser (`parser.py`) that implements the grammar in `docs/kpcl-language.md`.

```
PARK SLOT05          → Syntax Error: Expected VEHICLE_ID and SLOT_ID.
PARK SLOT05 CAR101   → Syntax Error (wrong token order).
```

## What is a context-free grammar?

A CFG describes nested/sequential structure with productions of the form `A → α`. KPCL’s command grammar is a small CFG. It cannot encode “the vehicle must exist in the database”; that is semantic, not syntactic.

## What is semantic analysis?

Semantic analysis checks **meaning** using context (here, the SQLite database): entity existence, uniqueness, slot occupancy, parking state, and payable records (`semantic.py`). No database writes occur in this phase.

```
PARK CAR999 SLOT05  → Semantic Error: Vehicle CAR999 is not registered.
```

## What is intermediate code?

After analysis, the compiler emits a list of simple instructions (`intermediate_code.py`), independent of React widgets:

```json
[
  { "instruction": "LOAD", "operand": "CAR101" },
  { "instruction": "CHECK", "operand": "SLOT05" },
  { "instruction": "ASSIGN", "operand": "CAR101, SLOT05" },
  { "instruction": "UPDATE STATUS", "operand": null }
]
```

This is analogous to three-address / quadruple-style IR used in textbooks, scaled to a command language.

## What is error handling?

Each phase raises a typed exception (`errors.py`): `LexicalError`, `KPCLSyntaxError`, `SemanticError`. `pipeline.py` catches them and returns a structured JSON payload (`error_type`, `message`, tokens so far, validity flags). Stack traces are not sent to the browser.

## How the KPCL compiler works (end to end)

1. UI posts `{ "command": "..." }` to `POST /api/compiler/execute/`.
2. `pipeline.compile_script` splits lines and runs `compile_command` for each.
3. Lexer → Parser → Semantic analyzer → IR generator.
4. Only then `executor.py` calls parking/payment services inside transactions.
5. The response includes tokens, syntax/semantic flags, IR, execution result, and `stages_completed` for the visual pipeline.

Source files for the viva:

- `lexer.py` — scanning
- `parser.py` — CFG / recursive descent
- `semantic.py` — context-sensitive checks
- `intermediate_code.py` — IR
- `executor.py` — backend actions
- `pipeline.py` — phase orchestration
